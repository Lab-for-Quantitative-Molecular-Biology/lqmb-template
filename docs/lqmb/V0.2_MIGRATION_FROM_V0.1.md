# LQMB v0.2 migration from v0.1

## Purpose

Version 0.2 introduces the explicit living-project dependency model. It does not recreate the project or replace project-specific work.

## Differences from v0.1

### Added

- `.lqmb/` project metadata namespace.
- `.lqmb/project.json` records the canonical LQMB template, adopted release and exact template commit.
- `.lqmb/dependencies.json` records software, project, dataset, method and publication dependencies.
- `.lqmb/manifest.json` distinguishes template-managed paths from protected project paths.
- `.lqmb/README.md` explains the metadata.
- `.lqmb/bin/template-status.py` provides a read-only local status check.
- `docs/lqmb/LQMB_LIVING_PROJECT_FRAMEWORK.md` explains the overall model.
- `docs/lqmb/TEMPLATE_UPDATE_PROTOCOL.md` specifies the safe update workflow.
- `docs/lqmb/V0.2_MIGRATION_FROM_V0.1.md` records this migration.

### Changed

- `CLAUDE.md` now checks template/dependency metadata at first substantive interaction.
- `CLAUDE.md` explicitly forbids automatic template updates and requires human approval.
- `CLAUDE.md` defines managed/protected-path behaviour and duplicate-update avoidance.
- `CLAUDE.md` clarifies that `data/` is not a default raw-data store.
- AI provenance now requires structured Git trailers and forbids claiming human review before it occurs.
- `CONTRIBUTING.md` now includes the template-update workflow.
- `README.md` documents the v0.2 living-project/dependency framework.
- `TEMPLATE_VERSION` advances from v0.1.0 to v0.2.0.

### Unchanged in principle

- The living-research philosophy.
- Contribution over hierarchy.
- Reproducibility and scientific honesty.
- The existing research-directory structure.
- The principle that project-specific code, data, results and manuscripts are protected from template replacement.
